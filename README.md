# espsdrtx

Arduino library for arbitrary I/Q transmission from an ESP32's Wi-Fi radio.

espsdrtx drives the Wi-Fi PHY's DAC replay engine through undocumented registers
found by others before it (see [Credits](#credits)).
You write up to 16383 complex samples (10-bit signed I and Q on the C3 and C6), and the radio plays them in a loop at 40 or
80 MS/s around a carrier in the 2.4 GHz ISM band. On top of that it provides packet
modulators (PSK/QAM, OFDM, FSK, chirp) and CPU-driven continuous streams (FM, PM, AM, QPSK).

It works as an Arduino library (`EspSdrTx`) and as an ESP-IDF component (`espsdrtx`).
So far it has been tested on the ESP32-C3 and the ESP32-C6 (see [Tested hardware](#tested-hardware)).

This is my first attempt at releasing an open source project so any feedback would be appricated.
A bit of a disclaimer, this code has been generated by claude, I have reviewed, tested and modified this code myself but its very likley I have missed something. 
Please let me know of any issues you find.

> This turns an ESP32 into a general-purpose transmitter. You are responsible for

## Quick start

Transmit a tone 1 MHz above a 2442 MHz carrier:

```cpp
#include <espsdrtx.hpp>
EspSdrTx tx;

void setup() {
  tx.begin(2442000);                       // carrier in kHz
  for (uint32_t k = 0; k < 16000; k++)     // 1 MHz tone: 200 whole cycles per loop
    tx.write(k, lroundf(100 * cosf(2 * (float)M_PI * (200 * k % 16000) / 16000)),
                lroundf(100 * sinf(2 * (float)M_PI * (200 * k % 16000) / 16000)));
  tx.start(16000, EspSdrTx::RATE_80M);     // loops until tx.stop()
}
void loop() {}
```

## Install

### Arduino

Copy or symlink this repository into your `Arduino/libraries` folder, or zip it and use
*Sketch > Include Library > Add .ZIP Library*. Select the board *ESP32C3 Dev Module* (or
*XIAO_ESP32C6* for the Seeed XIAO ESP32C6) and enable *USB CDC On Boot* to get `Serial`
over USB.

Examples: [`Tone`](examples/Tone), [`Packet`](examples/Packet),
[`FmTone`](examples/FmTone), [`AmTone`](examples/AmTone), [`PmTone`](examples/PmTone).

### ESP-IDF

Keep the directory named `espsdrtx` and either put it under your project's `components/`
or add it to `EXTRA_COMPONENT_DIRS`.

Example: [`examples/idf_tone`](examples/idf_tone) (run `idf.py build` from there).

When copying the library into another project, copy from a clean checkout
(`git archive`) or delete `examples/*/build` first, so no build output comes with it.

## API

The C API is in [`src/espsdrtx.h`](src/espsdrtx.h); the `EspSdrTx` C++ class in
[`src/espsdrtx.hpp`](src/espsdrtx.hpp) wraps the same calls. Every function is documented
where it is declared.

| Call | Description |
|---|---|
| `espsdrtx_begin(khz)` | Starts Wi-Fi in null mode (this powers the PHY) and tunes. Call once. |
| `espsdrtx_tune(khz, filter)` | Retunes, 2400000 to 2483500 kHz. `filter` 0: 21 MHz within 2 dB; 1: measured the same as 0; 2: about 35 MHz within 3 dB. |
| `espsdrtx_write(k, i, q)` / `espsdrtx_load(iq, n)` | Writes samples into the loop (clipped to ±511). Only while stopped. |
| `espsdrtx_set_dc(i, q)` | DC correction added to every sample written afterwards, to cancel the carrier leak. Rewrite the samples after changing it. Find the values per board and rate with a receiver. Sample plus offset clips at ±511. |
| `espsdrtx_start(n, rate)` | Plays samples `0..n-1` in a loop at `ESPSDRTX_40MSPS` or `ESPSDRTX_80MSPS`. |
| `espsdrtx_stop()` / `espsdrtx_running()` | Stops playback / reports whether it is playing. |
| `espsdrtx_allow_out_of_band(on)` | Lets `begin` and `tune` accept 2175000 to 2790000 kHz (except 2690000 to 2700000, radio astronomy). Off by default. **Read [Legal](#legal) first.** |

All calls except `espsdrtx_stop` and `espsdrtx_running` return an `esp_err_t`.

## Packet modulators

Declared in [`src/espsdrtx_mod.h`](src/espsdrtx_mod.h). Each modulator builds a whole
packet and writes it into the loop through a sink; on the chip that sink is
`espsdrtx_put`. They are plain C, so the same code also runs on a PC (e.g. to generate
reference waveforms for a receiver).

```cpp
uint32_t n = espsdrtx_sc_packet(data, len, seq, 2 /* QPSK */, 16 /* samples/symbol */, 25 /* rms */,
                                EspSdrTx::MAX_SAMPLES, espsdrtx_put, NULL);
if (n) tx.start(n, EspSdrTx::RATE_80M);   // n == 0: the packet does not fit the loop
```

| Call | Modulation | Tested on air |
|---|---|---|
| `espsdrtx_sc_packet` | BPSK, QPSK, 8-PSK, 16-QAM, 64-QAM (Gray), RRC 0.35 | QPSK, 8-PSK, 16-QAM at 80 MS/s |
| `espsdrtx_ofdm_packet` | OFDM, 802.11a numerology, BPSK to 64-QAM per subcarrier, scrambled; 80 MS/s only | QPSK, 16-QAM |
| `espsdrtx_fsk_packet` | 2-FSK, MSK, GFSK (BT ≥ 0.1), 4-GFSK | MSK, GFSK, 4-GFSK at 40 MS/s |
| `espsdrtx_css_packet` | Chirp spread spectrum (LoRa-like, **not** LoRa-compatible) | SF6, 10 MHz, at 40 MS/s |

Every packet uses the same framing: a preamble or sync word, a SIGNAL field (bits per
symbol, length, CRC), then the frame (a sequence byte, the payload and a CRC-32). A
receiver needs only the PHY parameters (rate, h, bandwidth, SF) and the preamble.

- **Build time:** a 16000-sample packet takes about 0.4 s (OFDM) to 0.9 s to build on the
  C3, which has no FPU.
- **Stop first:** a modulator returns 0 if the sink fails, and `espsdrtx_put` fails while
  TX is running, so stop before building the next packet.
- **No receivers** are included.

## Continuous streams

Declared in [`src/espsdrtx.h`](src/espsdrtx.h). The replay loop only repeats what it
holds, so for a signal that never repeats (audio, a data stream) the CPU rewrites one
word itself, one sample every `period` CPU cycles (160 MHz / 80 = 2 MS/s): a one-word
loop on the C3, the front end's TX DC register on the C6. A
callback supplies the data one byte at a time and ends the stream by returning a negative
value.

```cpp
static IRAM_ATTR int audio(void *ctx) { ... return next_byte; }   // or -1 to end
tx.fmStream(80 /* period */, 64 /* samples per audio byte */, 250000 /* offset Hz */,
            75000 /* deviation Hz */, 100 /* amplitude */, audio);
```

| Call | Modulation | Tested on air (2 MS/s) |
|---|---|---|
| `espsdrtx_fm_stream` | FM of 8-bit unsigned audio, one byte per `div` samples | Speech at 31.25 kS/s, 75 kHz deviation; 1 kHz tone at 5 and 75 kHz |
| `espsdrtx_pm_stream` | PM, phase deviation in radians | 1 kHz tone at 1 and 5 rad; at 5 rad as clean as FM at 5 kHz |
| `espsdrtx_am_stream` | AM, depth 0 to 1, `amp` is the peak | 1 kHz tone at depth 0.8, peak 100 |
| `espsdrtx_qpsk_stream` | QPSK of bytes (2 bits/symbol), RRC 0.35 over ±3 symbols, 2 to 16 samples/symbol | 250 and 500 ksym/s; a file sent in packets, bit-exact |

Things to know:

- **Interrupts are off** for the whole call, which blocks: no other task, timer or
  interrupt runs (the call feeds the watchdogs itself). Anything the callback reads must
  be polled or already in memory.
- **The callback runs between two samples:** keep it short and in RAM (`IRAM_ATTR`, data
  in `DRAM_ATTR`). With data in RAM, every sample arrived on time at 2.857 MS/s (FM, PM;
  period 56), 2.353 MS/s (AM) and 2.222 MS/s (QPSK), and FM decoded cleanly at 4 MS/s
  (period 40) with a few hundred samples slightly late. Fed from USB-Serial-JTAG, the data
  rate tops out between 131.6 kB/s (carried) and 138.9 kB/s (not).
- **Images:** each word is held until the next, so copies of the signal appear at
  multiples of the sample rate, attenuated only by the zero-order hold.
- **Arduino `Serial` afterwards:** Arduino's USB serial treats the host as gone and drops
  output until it reconnects, 5 to 15 ms later. Wait before printing:
  `while (!Serial) delay(5);` (with a timeout if no host may be attached).
- **AM level:** AM is the only stream whose envelope varies. Keep its peak `amp` under
  about 128, where the DAC at 80 MS/s starts to compress (peak 200 reduced a depth of 0.8
  to 0.72).
- **PM and receivers:** the transmitter's and receiver's oscillators drift apart in phase
  (mostly below 100 Hz), so a PM receiver has to track the carrier and pass only the audio
  band. FM's frequency detector is far less sensitive to this.
- **No framing:** `espsdrtx_qpsk_stream` sends bytes as they come. For packets, put a
  preamble and framing into the bytes yourself.

## Limits and costs

- **Chips:** ESP32-C3 (tested on ESP-IDF 5.5 and Arduino-ESP32 3.2.0, IDF 5.4) and
  ESP32-C6 (tested on Arduino-ESP32 3.2.0; the ESP-IDF build is not tried yet). Other
  targets fail the build with a message.
- **Wi-Fi:** the library takes over the radio; normal Wi-Fi cannot run alongside it.
- **NVS:** `espsdrtx_begin` erases the default NVS partition if it is full or from a newer
  format (as the ESP-IDF examples do).
- **Threads:** call espsdrtx from a single task; it keeps global state without locks.
- **RAM:** it reserves 128 KiB, which the RF block uses for the samples: on the C3
  `0x3fca0000..0x3fcbffff`, on the C6 `0x40840000..0x4085ffff`. If the program's static data reaches that region,
  `espsdrtx_begin` returns `ESP_ERR_NO_MEM`, and the ESP-IDF build fails at link time.
- **Loop length:** at most 16383 samples (205 µs at 80 MS/s). Pick a length where the
  waveform wraps without a discontinuity, e.g. a whole number of cycles of a tone.
- **Level:** there is no gain control, only the sample amplitude. The output compresses
  above about 256 at 40 MS/s and 128 at 80 MS/s (C3), and from about 200 at 80 MS/s (C6).
- **LO leakage:** the carrier leaks through as a DC term unless `espsdrtx_set_dc` cancels it.
  Streams leak more: on the C6 the leak grew with the stream rate (about -16 dBc at
  2 MS/s) and `espsdrtx_set_dc` did not cancel it, and in the FmTone example both chips
  leaked -23 dBc; keep stream signals offset from the carrier.
- **Undocumented internals:** the library relies on libphy functions Espressif does not
  document (on the C3: `g_phyFuns[50]`, `set_chanfreq`, `phy_set_freq`, ROM `pbus` calls;
  on the C6: `force_txon_mode`, `set_chanfreq`, `phy_set_freq`, ESP-IDF's
  `phy_track_pll_init`/`deinit`).
  A new IDF version may break them.

## Legal

- **Default:** the frequency range is limited to the 2.4 GHz ISM band. Keep the power low,
  or use a coax link with an attenuator.
- **Out of band (`espsdrtx_allow_out_of_band`) is not legal to radiate in most places.**
  Outside the ISM band you need a licence that covers the frequency (2300 to 2400 MHz is
  part of an amateur band in many countries, for licensed amateurs only). Otherwise
  transmit only into a dummy load or a coax link with an attenuator. The neighbouring
  bands carry satellite, telemetry and mobile services.
- The carrier locked from 2175 to 2790 MHz on the C3 board tested. Outside that range it
  sticks near an edge and wanders, so the library refuses those frequencies. On the C6
  out of band is not tried yet, so the library keeps it to the ISM band even when allowed.

## Adding a chip

Everything chip-specific lives in `src/hardware/<chip>/`: the replay engine's registers,
how libphy tunes, and the RAM the radio takes. The rest of the library (loop API, streams
and modulators) is shared. [`src/hardware/README.md`](src/hardware/README.md) lists what a
port has to provide.
